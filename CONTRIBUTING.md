# Contributing

1. Większą pracę zaczynaj od Issue.
2. Pracuj na osobnym branchu.
3. Otwórz Pull Request z opisem: co zmienia, dlaczego i jak to sprawdzić.
4. Nie commituj sekretów, tokenów ani prawdziwych danych dostępowych.
5. Zmiana zakresu wymaga aktualizacji `docs/requirements.md`.
6. Istotna decyzja techniczna powinna mieć ADR.
7. Ważniejsze zmiany w utrzymywanym projekcie powinny przejść co najmniej jedno review przed merge.
